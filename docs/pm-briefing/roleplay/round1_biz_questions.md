# 1라운드 — 사업 총괄 질문지 (기획자 경유 → 개발팀)

작성: 사업 총괄 (영업·재무·계약 책임). 2026-09-15.
근거: 개발팀 PoC 보고서(FACTS.md). 이 문서의 수치는 모두 그 보고서 인용이다. 보고서에 없는 수치는 `[추정]` 또는 `[모름/확인 필요]`로 표기했다.

## 전제

- 대기업 고객 두 곳이 "내년 상반기 공채에 쓸 수 있느냐"고 묻고 있다. 나는 아직 "예"도 "아니오"도 못 한다.
- 개발팀 보고는 "1개 세션, 3초 이내 발화 시작". 기획자 목표는 "동시 1000 세션, 완전 대화형, 실채용".
- 두 숫자 사이의 거리를 계약서에 쓸 수 있는 말로 바꾸는 것이 이 질문지의 목적이다.
- 보고서의 "3초"는 "말하기 클릭 → 음성 청크 생성 로그"까지다. 화면에 보이기까지는 6~7초다. STT·LLM은 빠져 있다. **이 정의 차이를 고객 앞에서 쓰기 전에 못 박아야 한다.**
- 법·규제 항목은 결론이 아니다. 전부 "법무 검토 필요"다. 개발팀에는 "기술적으로 가능한가"만 묻는다.

## A. 질문 목록 (33개)

우선순위 기준: **상** = 이 답 없이는 고객과 가격·일정 논의 불가. **중** = 계약서 초안 전까지 필요. **하** = 출시 전까지 필요.

### 1. 원가·단가·마진

#### Q1. 면접 1건 총원가
- **Q**: "보고서의 30분 면접 1건 $0.40(Lite) / $3.95(Pro)는 GPU만이다. TTS·STT·LLM·전송·CPU/메모리·운영 인건비 배부까지 합친 '면접 1건 총원가'는 얼마인가? 어느 항목이 아직 `[추정]`인가?"
- **왜 묻나**: 고객 제안서의 건당 단가와 마진율을 정한다. GPU만 보고 가격을 부르면 나중에 마진이 사라진다.
- **원하는 답 형태**: 항목별 원가표(GPU / CPU·메모리 / TTS / STT / LLM / 전송·TURN / 저장 / 운영 인건비 배부). 항목마다 실측·벤더 견적·추정 표기.
- **우선순위**: 상

#### Q2. 이용률별 건당 원가
- **Q**: "대기업 공채는 특정 주·시간대에 몰린다. GPU 이용률 30%·60%·90%일 때 건당 원가가 각각 얼마로 바뀌나?"
- **왜 묻나**: 건당 과금 / 좌석 / 월정액 중 가격 모델을 고른다. 이용률이 낮으면 건당 원가가 크게 뛴다.
- **원하는 답 형태**: 3개 시나리오 × Lite/Pro 표. 가정(평균 면접 길이, 피크 동시수) 명시.
- **우선순위**: 상

#### Q3. 예열·꼬리 등 숨은 고정비
- **Q**: "예열 1대 $19/일, 세션 종료 후 꼬리 과금 Lite $0.13 / Pro $0.66. 1000 세션 규모에서 예열 풀을 몇 대, 얼마나 오래 유지해야 하나? 건당으로 환산하면 얼마인가? 꼬리 과금은 줄일 수 있나?"
- **왜 묻나**: 건당 원가 뒤에 숨은 고정비다. 공채 없는 달에도 나가는 돈인지 판단해야 한다.
- **원하는 답 형태**: 성수기/비수기 두 가지 월 고정비. 유휴 종료 대기 시간(Lite 600 s, Pro 300 s)을 줄일 때의 부작용.
- **우선순위**: 중

#### Q4. Lite를 팔 수 있는 화질인가
- **Q**: "Pro는 Lite보다 GPU 원가가 약 10배(산술: $3.95 vs $0.40)다. 보고서에 Lite는 '입술 뭉개짐'이라고 적혀 있다. Lite를 고객에게 팔 수 있나, 아니면 Pro가 최소선인가?"
- **왜 묻나**: 상품 등급(베이직/프리미엄)과 가격표를 짠다. Pro만 가능하면 1000 세션 사업성이 근본적으로 달라진다.
- **원하는 답 형태**: 두 등급 샘플 영상. 고객 HR 담당자 시연 반응(있으면). 예/아니오.
- **우선순위**: 중

#### Q5. 견적 계산 변수
- **Q**: "고객당 월 비용을 계산하려면 어떤 변수가 필요한가? 변수 목록과 계산식을 개발팀이 정의해 달라."
- **왜 묻나**: 영업이 견적을 낼 때마다 개발팀에 묻지 않으려면 계산 도구가 있어야 한다.
- **원하는 답 형태**: 변수 목록(세션 수, 평균 길이, 피크 동시수, 예열 대수, 리전, 재시도율, 등급) + 계산식이 든 스프레드시트.
- **우선순위**: 중

### 2. 비용 폭주 시나리오

#### Q6. 지출 상한
- **Q**: "예열을 끄는 것을 잊으면 $19/일/대가 계속 나간다. 배포마다 예열 설정이 초기화된다는 점도 반대로 사고를 부를 수 있다. Modal에 월 지출 상한(하드 캡)을 걸 수 있나? 일 단위 지출 알림은 받을 수 있나?"
- **왜 묻나**: 재무는 '최악의 달' 상한을 알아야 예산을 승인한다. 상한이 없으면 예산 승인 불가.
- **원하는 답 형태**: 예/아니오. Modal 콘솔의 지출 한도·알림 기능 캡처 또는 문서 링크. 없으면 자체 차단 장치 설계안.
- **우선순위**: 상

#### Q7. 유령 세션
- **Q**: "지원자가 브라우저를 닫거나 네트워크가 끊겨도 세션이 열려 있으면 GPU가 계속 과금된다. 유령 세션을 몇 초 안에 감지해 강제 종료하나? 세션 최대 길이 상한이 있나?"
- **왜 묻나**: 1000 세션 중 일부만 안 닫혀도 시간당 $0.80~$7.90씩 샌다.
- **원하는 답 형태**: 감지 방식, 타임아웃(초), 최대 세션 길이. 미구현이면 미구현이라고.
- **우선순위**: 상

#### Q8. 재시도 폭풍
- **Q**: "서울 리전에서 L4 6대 동시 요청이 240초 안에 배정되지 않은 적이 있다. 배정 실패 때 재시도가 일어나면 컨테이너가 중복 생성되어 과금되나? 재시도 폭풍의 최대 과금액은?"
- **왜 묻나**: 장애가 곧 비용 폭증이 되는 구조인지 알아야 한다.
- **원하는 답 형태**: 재시도 정책(횟수·간격·중복 방지) 문서. 최악 시나리오 과금 산출.
- **우선순위**: 중

#### Q9. 벤더 가격 변동
- **Q**: "리전 배수(`jp` 1.75×)가 09-10 메모와 09-14 청구서에서 다르다. 현재 가격표를 재확인해 달라. Modal이 가격을 올리면 우리 원가는 얼마나 흔들리고, 사전 고지 기간은 얼마인가?"
- **왜 묻나**: 고객과 1~2년 단가를 고정하려면 벤더 가격 변동 조건을 알아야 한다.
- **원하는 답 형태**: Modal 현재 가격표(확인 날짜 표기)와 약관의 가격 변경 조항. GPU 단가 변동 시 건당 원가 변화 표.
- **우선순위**: 중

### 3. 계약·SLA

#### Q10. 약속 가능한 가용성
- **Q**: "우리 서비스는 Modal + TTS + STT + LLM + 전송이 직렬로 묶인다. 각 벤더가 문서로 약속하는 가용성은 얼마인가? 다 곱하면 우리가 고객에게 약속할 수 있는 가용성은 몇 %인가?"
- **왜 묻나**: 고객 SLA 조항의 숫자다. 한 벤더만 빠져도 전체가 멈추므로 가장 약한 벤더가 기준이 된다.
- **원하는 답 형태**: 벤더별 SLA 문서 링크 + 합성 가용성 계산. SLA가 없는 벤더는 '없음'으로.
- **우선순위**: 상

#### Q11. 지연 목표의 정의와 실측
- **Q**: "'3초'는 '말하기 클릭 → 음성 청크 생성 로그'다. 화면에 보이기까지는 6~7초다. STT·LLM은 빠져 있다. 지원자가 말을 끝낸 뒤 아바타가 답하기 시작할 때까지의 전체 지연은 실제로 몇 초인가? p50·p95로."
- **왜 묻나**: 고객은 "3초"를 계약에 쓰려 할 것이다. 어느 구간의 3초인지 정의 없이 쓰면 패널티 분쟁이 된다.
- **원하는 답 형태**: 구간 정의 표(지원자 발화 종료 → STT → LLM 첫 토큰 → TTS 첫 패킷 → 렌더 → 화면). 구간별 p50/p95. 미측정 구간은 `[모름]`.
- **우선순위**: 상

#### Q12. 면접 시작 대기 시간
- **Q**: "콜드 스타트가 Lite 85~125초, Pro 약 50초다. 지원자가 입장 후 2분 가까이 기다리는 게 허용되나? 예열되어 있으면 몇 초인가? '입장 후 N초 내 면접 시작'을 계약에 쓸 수 있나?"
- **왜 묻나**: 지원자 경험 조항과 패널티 기준이다. 2분 대기는 고객 HR이 받아들이지 않을 가능성이 크다 `[추정]`.
- **원하는 답 형태**: 예열/콜드 두 가지 실측(초). 예약 배치(T−3~5분) 시 배정 실패율.
- **우선순위**: 상

#### Q13. 패널티 재원과 벤더 SLA 전가
- **Q**: "공채 당일 하루 장애로 면접 1000건이 무효가 되면 우리 손실은 어디까지인가? Modal 셀프서브 약관에 SLA·크레딧 조항이 있나? 벤더 크레딧을 고객 패널티 재원으로 쓸 수 있나?"
- **왜 묻나**: 책임 한도 조항과 보험 가입 판단. 벤더 SLA를 전가하지 못하면 패널티는 전액 우리 부담이다.
- **원하는 답 형태**: Modal 약관(SLA·책임 한도) 원문. 각 벤더의 SLA 크레딧 조건.
- **우선순위**: 상

#### Q14. 동시 세션 수 서면 확인
- **Q**: "Modal 워크스페이스의 동시 GPU 쿼터를 확인하지 않았다고 되어 있다. L4 1000대 또는 H100 2000장을 서울·도쿄에서 확보 가능한지 Modal에 서면으로 확인해 달라. 엔터프라이즈 계약이 필요하면 조건과 리드타임은?"
- **왜 묻나**: '동시 1000 세션'을 계약서에 쓰려면 벤더 서면 확인이 필요하다. 구두 답변은 계약 근거가 안 된다.
- **원하는 답 형태**: Modal 영업의 서면 답변(리전별 확보 가능 대수, 예약 가격, 최소 약정, 계약 기간).
- **우선순위**: 상

### 4. 고객 실사

#### Q15. 데이터 흐름도와 위치
- **Q**: "GPU는 서울(GCP asia-northeast3)이지만 제어·로그·큐는 미국 인프라를 거칠 수 있다고 한다. 지원자 음성·영상·텍스트가 실제로 어느 나라의 어느 시스템을 거치고 어디에 저장되는지 흐름도를 그려 달라."
- **왜 묻나**: 보안 질의서 1번 항목이 '데이터 위치'다. 국외 이전 여부 판단의 출발점이다.
- **원하는 답 형태**: 데이터 흐름도. 홉마다 위치·보관 여부·보관 기간·암호화 표기. 모르는 홉은 `[모름]`.
- **우선순위**: 상

#### Q16. 재하청(수탁자) 목록
- **Q**: "재하청 목록을 만들어 달라. Modal(GCP), TTS, STT, LLM, 전송(TURN) 벤더. 각각 지원자 데이터 중 무엇을 받고, DPA(위탁 계약) 체결이 가능한가? 받은 데이터를 모델 학습에 쓰나?"
- **왜 묻나**: 고객 DPA에 수탁자 명단을 써야 한다. 지원자 음성이 해외 LLM/STT 벤더로 넘어가면 별도 동의·계약 문제가 생긴다.
- **원하는 답 형태**: 벤더별 표(역할, 받는 데이터, 위치, DPA 가능 여부, 학습 사용 여부). 미확정 벤더는 후보로 표기.
- **우선순위**: 상

#### Q17. 암호화·접근 통제·보관
- **Q**: "전송 중·저장 시 암호화는? 녹화 mp4와 세그먼트 파일에 누가 접근 가능한가? 보관 기간과 파기 절차는? 현재 PoC는 Mac에 세그먼트 파일이 그대로 남는다."
- **왜 묻나**: 질의서 필수 항목이다. 답이 없으면 실사에서 떨어진다.
- **원하는 답 형태**: 문서(암호화 방식, 접근 권한 표, 보관·파기 정책 초안). 현재 상태와 목표 상태를 구분.
- **우선순위**: 중

#### Q18. 인증 보유
- **Q**: "우리와 벤더가 보유한 인증(ISMS-P, ISO 27001, SOC 2 등)은 무엇인가? Modal의 컴플라이언스 문서를 받을 수 있나?"
- **왜 묻나**: 대기업 정보보호팀은 인증 유무로 1차 필터한다. ISMS-P 요구 가능성은 `[확인 필요]`.
- **원하는 답 형태**: 인증서 사본 또는 '없음'. 벤더 문서 링크.
- **우선순위**: 중

### 5. 규제·법무 (전부 법무 검토 필요 항목)

#### Q19. AI 표시·고지·평가 근거 기록
- **Q**: "AI 기본법(2026-01-22 시행)상 채용 판단 AI가 고영향 AI인지, 생성물 표시 의무가 있는지는 법무가 확인한다. 개발팀에는 이것만 묻는다. 화면에 'AI와 대화 중' 고지와 아바타 영상에 'AI 생성' 표시를 넣을 수 있나? 평가 근거를 지원자별로 로그로 남길 수 있나?"
- **왜 묻나**: 해당되면 출시 조건이 된다. 계약서에 준수 의무 조항이 들어간다.
- **원하는 답 형태**: 예/아니오 + 구현 공수. 법무에는 검토 의견서를 별도로 요청.
- **우선순위**: 중

#### Q20. 국내 전용 구성 가능성
- **Q**: "Modal은 미국 기업이다. 국외 이전 고지·동의가 필요할지는 법무가 확인한다. 개발팀에는 이것만 묻는다. 지원자 데이터가 국내 인프라만 거치는 구성(예: 국내 클라우드 전용 GPU)이 기술적으로 가능한가? 비용과 일정 차이는?"

#### Q22. 장애 지원자 구제를 위한 기록

## D. 사업 총괄이 개발팀에 요구하는 답변 형식·증빙

1. **원가는 시나리오 표로.** 이용률 30/60/90% × Lite/Pro 6칸. GPU 외 항목(TTS·STT·LLM·전송·저장)은 벤더 견적서를 첨부하고, 견적이 없으면 `[추정]`으로 표기. 인건비는 직무·인원·기간만 적고 단가는 비워 둔다(재무가 채운다).
2. **지연은 구간 정의 표 + p50/p95로.** "3초" 단독 사용 금지. 지원자 발화 종료부터 화면 표시까지 전 구간을 나누고, 미측정 구간은 `[모름]`. STT·LLM을 넣은 뒤 재측정한 값이 없으면 "PoC 텍스트 입력 기준"을 반드시 병기.
3. **벤더 조건은 문서로.** Modal의 쿼터·SLA·가격표·책임 한도·DPA 가능 여부는 서면(이메일·약관 링크·화면 캡처). 구두 확인은 근거로 인정하지 않는다. TTS·STT·LLM 후보 벤더도 같은 형식.
4. **모든 수치에 출처 표기.** 실측(날짜·조건) / 벤더 문서 / 추정 / 모름 네 가지 중 하나. 보고서 §0 규칙 그대로 적용.
5. **단계 계획에는 관문(gate)을.** 5~10 → 50 → 1000 각 단계에 진입 조건, 검증 항목, 실패 시 중단 기준을 적는다. "가능할 것 같다"는 표현은 쓰지 않는다. 각 단계에서 고객 계약서에 쓸 수 있는 문구를 함께 제안한다.
