# 스파이크 2: 생성 → 대기 루프 복귀

`spike-seam`이 루프 → 생성 방향은 공짜임을 보였다. 발화가 **끝날 때**도 루프로
돌아가야 하는데, 루프 프레임은 고정돼 있고 마지막 생성 프레임은 그때그때 다르다.
네 가지 복귀 전략을 자연스러운 프레임 간 변화와 비교했다.

## 결과 (L4, Lite, newscaster, 2026-09-17)

기준: 프레임 간 자연 변화 — 무음 루프 0.58(h264로 평활됨), 발화 중 2.70.

| 전략 | 복귀 점프 | 판정 |
|---|---|---|
| R1 루프 첫 프레임으로 컷 | 6.25 | 보인다 (발화 중 변화의 2.3배) |
| R2 가장 가까운 루프 프레임으로 컷 | 6.25 | 동일 — 최근접 탐색이 도움이 안 된다 |
| **R3 최근접 + 4프레임 크로스페이드** | **1.66** | **보이지 않는다** (자연 변화 아래) |
| R4 무음 2청크 생성 후 페이드 | 2.08 | 더 낫지 않고 GPU만 더 쓴다 |

**최근접 탐색은 무의미했다** — 240프레임 루프 전체가 마지막 발화 프레임과
비슷하게 멀다(모두 6.2 안팎). 루프는 거의 정지한 중립 얼굴인데 발화 마지막
프레임은 입이 열려 있어서, 맞는 프레임이 아예 없기 때문이다. 해법은 "맞는
프레임 찾기"가 아니라 **섞기**다.

R4가 R3보다 나쁜 것도 같은 이유다. 무음을 더 생성해 입을 닫아도 루프와의 거리는
줄지 않고(6.38), GPU 2청크만 더 쓴다.

## 채택

**R3 — 4프레임(160 ms) 크로스페이드.** 가장 단순하고 GPU를 쓰지 않는다.
`Renderer.live()`의 `fade_frames` 기본값이 이 값이다.

재현: `modal run app.py::ret`
